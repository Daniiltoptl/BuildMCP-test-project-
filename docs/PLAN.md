# BuildMCP: плагин-MCP для постройки про-спавнов в Minecraft 1.21.x

## Контекст

Нужен набор инструментов, с которым я (Claude) строю спавны уровня топ-серверов (и лучше FunTime): планирую, строю, вижу результат глазами, правлю и сам вставляю на сервер.

Что известно из ответов:
- сервер на **1.21.x**;
- меня запускают **локально на ПК** (Claude Code или Desktop);
- на сервер вставляю **я сам**, способ выбираю по качеству;
- первые стили: **фэнтези/средневековье, Азия/сакура, тёмный/адский, зима/север**.

Репозиторий пустой (нет ни одного коммита), проект делается с нуля. Писать буду здесь, в облачной сессии. Отсюда доступны PyPI, npm, GitHub raw и Maven Central. Mojang, PaperMC, Modrinth и EngineHub закрыты сетевой политикой. Поэтому Java-мост собираю и тестирую на настоящем сервере в GitHub Actions. Текстуры для рендера в облаке беру с зеркала на GitHub, на ПК пользователя берутся с Mojang.

## Ключевые решения

1. **Упаковка.** Плагин Claude Code, репозиторий сразу служит маркетплейсом. Внутри MCP-сервер, skill-методичка «как строить про-спавн», агент-критик и слэш-команды. Установка: `/plugin marketplace add Daniiltoptl/BuildMCP-test-project-`, потом `/plugin install buildmcp@buildmcp`.
2. **Движок на Python** (numpy, scipy, numba, Pillow, nbtlib, trimesh), запуск через `uv`. Почему Python: объёмные булевы операции, SDF, морфология и сглаживание террейна, быстрый рендер на numba, вокселизация 3D-моделей.
3. **Главный инструмент — `run_script`.** Я пишу процедурные скрипты на API движка: острова, деревья, крыши, дороги. Скрипты сохраняются в проект как пайплайн шагов, поэтому любую сборку можно пересобрать с изменёнными параметрами. Простые правки делаются прямыми инструментами.
4. **Глаза — собственный рейтрейсер** с настоящими ванильными blockstates, моделями и текстурами версии сервера. Он правильно рисует ступени, плиты, заборы, листву с прозрачностью, воду, стекло и display-сущности. Есть режимы день, закат и ночь с реальным светом от блоков. Есть вид от глаз игрока, изометрия и карта сверху с сеткой координат и маркерами. Картинка возвращается прямо в ответе инструмента.
5. **Доставка на сервер (лучшее качество): свой мост BuildBridge.** Это плагин для Paper 1.21 поверх WorldEdit или FAWE. Вставка идёт 1:1 без физики, то есть ничего не падает, не течёт и не отваливается. Корректно переносятся NBT, головы, таблички и display-сущности. Вставка фоновая, чанками, без лагов. Перед каждой вставкой делается бэкап, поэтому есть undo. Мост умеет читать мир (рельеф и старый спавн), позицию игрока и его WE-выделение, телепортировать игрока к точкам обзора. **Запасной путь — RCON**: ничего ставить не надо, но медленнее, с физикой и без чтения мира. Экспорт `.schem` доступен всегда.

## Движок `server/src/buildmcp/`

- **blocks/**
  - `registry`: состояния блоков по версиям 1.21…1.21.11 и 26.1. Данные вшиты компактно из minecraft-data, плюс DataVersion. При подключённом мосте берётся реестр самого сервера. Канонизация `id[props]`, валидация с подсказками «возможно, вы имели в виду».
  - `families`: семейства материалов (блок, ступени, плита, стена, забор).
  - `transforms`: поворот и отражение с корректным пересчётом facing, axis, rotation, shape, hinge и соединений.
  - `finalize`: проход «как после обновлений в игре». Считает соединения заборов, стен, панелей и решёток, углы ступеней, ставит `persistent=true` листве, достраивает двойные растения, двери и кровати, выставляет snowy и waterlogged, висячие фонари.
- **scene / project**
  - Плотный объём uint16 с автоматическим ростом, палитра, block entities, сущности, биомы (влияют на цвет травы и листвы) и маркеры.
  - Проект на диске: `builds/<name>/` со сценой в `.npz` и json, пайплайном `scripts/NN_*.py`, папками `renders/`, `exports/` и `history/`.
  - Чекпоинты и undo хранятся как сжатые снимки.
- **geo/**
  - Маски с булевыми операциями, выделения поверхности (верх, бока, кромки, открытые грани).
  - SDF-примитивы: шар, эллипсоид, цилиндр, конус, тор, капсула, призмы, арки, спирали, трубы по Безье и сплайнам, вращение профиля, выдавливание 2D.
  - Плавные объединения и шумовое смещение.
  - `smooth`: сглаживание поверхностей ступенями и плитами, как у про-терраформеров.
- **paint/**
  - Палитры: взвешенные, шумовые смеси, градиенты по высоте, оси, расстоянию и нормали.
  - Шумы: simplex, fBm, ridged, Worley.
  - Состаривание: мох, трещины, накладки.
  - Цветовые градиенты блоков в пространстве LAB.
- **gen/**
  - `terrain`: летающие острова с детальным низом, скалы со слоями, пруды и реки, водопады.
  - `trees`: не меньше 8 архетипов: гигантский фэнтези-дуб, ива, сакура, ель со снегом, мёртвое дерево, гигантский багровый гриб, куст, живая изгородь.
  - `rocks`: валуны, кристаллы, шипы, сосульки.
  - `paths`: дороги по сплайну со смешанной кромкой и авто-ступенями, мосты.
  - `arch`: стены с глубиной, окна, двери, крыши (двускатная, вальмовая, мансардная, купол, конус, изогнутая азиатская, скандинавская), башни, арки, колонны, готика.
  - `props`: фонари, лавки, фонтаны, торii, каменные тōрō, жаровни, порталы режимов с местом под NPC.
  - `text`: объёмные 3D-логотипы из пиксельных шрифтов или TTF.
  - `entities`: text, block и item display, головы с текстурами, таблички, баннеры, с учётом версии формата NBT (1.21.5+).
  - `image`: пиксель-арт и heightmap из картинки.
  - `model`: .obj, .glb и .stl в блоки с подбором по цвету, для статуй.
- **themes/**: `fantasy_medieval`, `asian_sakura`, `dark_infernal`, `winter_north`. В каждой палитры по ролям (грунт, скала, дорога, стены, отделка, крыша, листва, свет, акцент, жидкость) и настройки генераторов по умолчанию.
- **render/**
  - `assets`: сначала client.jar с Mojang, при недоступности зеркало на GitHub. Кэш в `${CLAUDE_PLUGIN_DATA}`, текстуры в репозиторий не коммитятся.
  - `models`: разбор blockstates (variants и multipart), наследование моделей, элементы с поворотами x/y. Блоки, которые игра рисует отдельно (сундук, кровать, табличка, баннер, голова и т.д.), аппроксимируются.
  - `raytrace` на numba parallel:
    - проход по вокселям методом DDA и пересечение с элементами модели;
    - вырезанная и полупрозрачная прозрачность;
    - тени от солнца, AO, туман и небо;
    - биомные оттенки;
    - ночью свет считается распространением BFS, как в игре;
    - display-сущности рисуются как ориентированные боксы.
  - Виды:
    - `iso` в 4 направлениях, `persp` и `player` (глаза на 1.62 от маркера), `orbit`;
    - `top`: карта с сеткой каждые 8/16 блоков, подписями координат и маркерами;
    - `elev` (фасады), `section` (срез по Y);
    - `sheet`: контактный лист из 4–6 видов;
    - `diff`: подсветка изменений.
- **io/**
  - Sponge `.schem` v3 и v2: чтение и запись, с block entities, сущностями и биомами.
  - Импорт `.nbt` (структуры) и `.litematic`, для паков ассетов.
  - `.mcfunction`.
- **analyze/**
  - `stats`.
  - `lint`: невалидные для версии блоки, «висящие» факелы и растения, гравитационные блоки без опоры, большие плоские однотонные плоскости и стены без глубины (с координатами), тёмные зоны ночью, вода, которая потечёт, бюджет сущностей.
  - `walk`: проходимость от точки спавна до всех NPC и порталов, высота ступеней, 2 блока над головой, обрывы без перил.
- **live/**: `bundle` (формат обмена с мостом), `bridge` (httpx), `rcon` (строго последовательный протокол, пакеты ≤ 1460 байт), `placer` (кубоиды greedy на numba, фазы: твёрдые, навесные, жидкости, NBT, сущности, биомы; `strict` на 1.21.5+, длинный NBT делится на несколько `data merge`), `deploy` (смещение сцены в мир, перевод палитры под версию сервера, очистка удалённых блоков по прошлой вставке, записи о вставках), `connector` (мост, если есть, иначе RCON). Бэкапа через RCON нет: это запасной путь.
- **scripting**: пространство имён для `run_script`: `S`, `M`, `P`, `T`, `gen.*`, `E`, `rng`, `np`. Таймаут-сторож и захват stdout. Документация генерируется из docstring для `api_docs`.

Соглашения API: x смотрит на восток, y вверх, z на юг. Регионы включительные `[x1,y1,z1,x2,y2,z2]`. Везде, где принимается блок, можно передать строку, палитру, материал или функцию от (x,y,z). У всех генераторов есть `seed`.

## Мост BuildBridge (`plugins/buildmcp/bridge`)

> Изменение по ходу этапа 5: мост работает на чистом Paper API, WorldEdit/FAWE не нужен
> (меньше зависимостей у пользователя, нет расхождений API WE и FAWE). Качество вставки то же.

- Java 21 и Gradle, компиляция против `paper-api 1.21.1` (подходит для всех 1.21.x). Типы, которые
  внутри 1.21.x стали из enum интерфейсами (Biome), используются только через `Keyed`.
- HTTP на встроенном `com.sun.net.httpserver`. По умолчанию слушает `127.0.0.1:8765`, авторизация по
  Bearer-токену (генерируется в `config.yml`), опционально список разрешённых IP.
- Формат обмена — «бандл» BMCB (gzip): JSON-заголовок (палитра состояний, NBT блоков и сущностей в SNBT,
  биомы, опции) и массив u16 индексов. Индекс 0 = «не трогать блок мира».
- Эндпоинты `/v1`:
  - `ping` (без токена), `status`: версия, DataVersion, миры, игроки, TPS, задачи;
  - `players`, `players/{name}`: позиция, взгляд, блок под прицелом, выделение WorldEdit (через reflection, если WE стоит);
  - `paste`: задача. Чанки грузятся асинхронно и держатся тикетами. Снимки чанков → бэкап изменяемых
    ячеек (+ NBT блоков через `/data get`, сущности с тегом проекта) → анализ вне главного потока
    (совпадающие блоки пропускаются) → удаление старых сущностей проекта → блоки `setBlockData(.., false)`
    порциями по тикам (бюджет `max-tick-millis`) → NBT (`data merge block`) → сущности (`summon`) → биомы (`fillbiome`);
  - `jobs`, `jobs/{id}`, `jobs/{id}/cancel`, `backups`, `undo` (восстанавливает блоки, NBT, сущности и биомы);
  - `region`: чтение бокса мира в бандл; `heightmap`; `command` (вывод захватывается тихим отправителем
    Paper, без спама операторам); `teleport`.
- Команда `/bb status | jobs | cancel | backups | undo | token | reload`.
- Тесты без Minecraft: `bridge/testkit` содержит заглушки нужной части Paper API и поддельный сервер
  (мир с чанками и тикетами, проверки главного потока, `data`/`summon`/`fillbiome`). Python-тесты
  запускают настоящий код моста в нём и проходят вставку, чтение, повторную вставку, отмену.
- CI (`bridge.yml`):
  - сборка против настоящего paper-api;
  - e2e на Paper 1.21.1, 1.21.4, 1.21.8 и последней версии: вставка витрины (дом, дерево, фонари,
    таблички, баннер, голова, display-сущности, вода, биом), чтение обратно и сравнение 1:1, повторная
    вставка без изменений, двойная отмена, RCON-фолбэк, сверка `finalize` с игрой (заборы, панели, стены,
    калитки, ступени, снег, грибные блоки, капельники, лианы ставятся с обновлениями, сравниваются с нашим расчётом);
  - на тег `bridge-v*` выходит GitHub Release с jar.

## Методичка (skill) и критик

- `SKILL.md` описывает рабочий цикл:
  1. бриф;
  2. раскладка зон на карте `top`: точка спавна с направлением взгляда, центральный акцент, кольцо порталов и NPC, декоративные зоны, граница;
  3. грубые объёмы (blockout), затем рендеры;
  4. террейн и органика;
  5. детализация архитектуры;
  6. свет;
  7. логотип и голограммы;
  8. `lint` и `walk`, ночной рендер;
  9. критик;
  10. вставка с бэкапом;
  11. телепорт игрока по точкам обзора;
  12. итерации.
- `references/`: композиция и масштаб, палитры 1.21 по темам с пометками, с какой версии есть блок, глубина и детализация, органика, свет, функциональная часть спавна (регион, защита от падения в пустоту, NPC, text display, производительность), чек-лист критика.
- `agents/build-critic.md`: сам делает `render`/`inspect` и возвращает приоритизированные правки с координатами.

## Проверка

- `cd plugins/buildmcp/server && uv run pytest`:
  - канонизация и валидация состояний;
  - поворот 4 раза и двойное отражение дают исходное;
  - правила finalize: углы ступеней, стены, панели, двойные блоки;
  - round-trip `.schem` v3/v2 и чтение независимым ридером;
  - правила lint и walk;
  - детерминизм генераторов;
  - все сгенерированные состояния валидны для 1.21.4 и 1.21.11.
- Рендер: тестовые сцены со ступенями, заборами, листвой, водой, стеклом и display-сущностями. Смотрю их сам через Read. Замер скорости: цель ≤ 3 с на 1280×720 для сцены 200×100×200 после прогрева JIT.
- MCP e2e через stdio-клиент: `tools/list` → `project_create` → `run_script` → `render` (приходит изображение) → `export` → повторный импорт даёт идентичный результат.
- `claude plugin validate .` и `claude plugin validate plugins/buildmcp` (CLI 2.1.282 здесь есть).
- GitHub Actions: Python на ubuntu и windows, мост на реальном Paper и WorldEdit. Слежу через GitHub MCP до зелёного.
- Демо: рендеры днём, ночью и от глаз игрока, плюс проход критика.
- У тебя на ПК: установить плагин, выполнить `/buildmcp:setup`, увидеть зелёный `server_status`, вставить демо с бэкапом и проверить `server_undo`.

## Что понадобится от тебя потом

1. Установить `uv` (одна команда, дам её).
2. Сервер Paper (или форк) 1.21.x. WorldEdit не обязателен.
3. Положить BuildBridge.jar в `plugins/`. Если сервер на этом же ПК, можно дать путь к папке сервера, тогда `bridge_install` сделает это сам.
4. Вписать токен в настройки плагина.
5. Необязательно: включить RCON как запасной путь.

## Риски

- **Первый запуск долгий (установка зависимостей).** Решение: фоновый `uv sync` в SessionStart и `/buildmcp:setup`.
- **Numba.** Python закрепляю на 3.12 через uv, CI на Windows.
- **Форматы NBT отличаются внутри 1.21.x.** Решение: писатели с учётом версии и матрица e2e.
- **Разница WE и FAWE.** Снята: мост не зависит от WorldEdit.
- **Нельзя проверить на твоём сервере из облака.** Всё серверное проверяется в CI на настоящем Paper.
